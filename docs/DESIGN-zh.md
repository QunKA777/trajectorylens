# 掉落物(ItemEntity)轨迹预测 Mod — 设计方案

目标: 为 **Minecraft Java 26.2 (Fabric)** 开发一个服务端/客户端均可安装的 Mod,实时预测掉落物的运动轨迹并在世界中绘制弧线、落点标记与预计落地时间。本文为可行性方案。

## 1. 目标与非目标

### 目标 (v1)
- 客户端: 对玩家附近的掉落物实时预测未来运动轨迹(≥ 数百 tick/数十秒),绘制:
  - 3D 轨迹折线(随时间渐变色或速度色);
  - 终点/静止落点标记 + 预计落地或静止的时间 (ETA);
  - 穿墙/被遮挡显示策略可配置。
- 服务端: 同一 jar 可安装到纯服务端,**启动零报错、零副作用**(客户端逻辑不加载);
- 本地预测偏差极小(重力抛物场景 < 1 格),复杂环境(水流/气泡柱/岩浆)有界并可自我修正。

### 非目标 (v1)
- 预测被玩家/生物捡起、被玩家走位碰撞推挤后的事件结果(不可知因素,改为"终止并清除显示");
- 服务端权威轨迹广播给其他玩家(列为 v2 可选,见 §7-B);
- 修改物品物理本身(纯预测、不改动原版行为)。

## 2. 可行性论证: 为什么"预测"能成立

掉落物的运动由 **服务端每个 tick 的确定性代码**驱动,客户端持有相同版本代码 + 与服务端一致的区块/流体状态副本:

1. **确定性**: 同版本下物理常量与算法一致 → 客户端可以用"影子仿真"精确重放服务器将要做的事;
2. **单机 (integrated server)**: 仿真与实体 tick 在同一 JVM,理论零偏差;
3. **联机**: 客户端看到的实体位置/速度由服务器同步,本地世界状态与服务器一致(已加载区块) → 无外力干扰时仿真同样精确;
4. **外部扰动如何处理**: 玩家/生物推挤、拾取、合并、消失属于"事件",仿真以这些为**终止条件**(一旦真实实体消失/被拾取即清除轨迹; 每 1~2 tick 与真实实体状态对账,偏差超过阈值立即重算)。视觉上表现为"实时修正",而非错误持续。

风险: 需要**逐 tick 复刻 ItemEntity 的完整运动分支**,包括: 空气阻力/重力、地面摩擦、流体(水/熔岩)浮力与阻力、气泡柱、蜘蛛网减速、被水流推动、碰撞反弹(投掷物撞墙)、传送门等。→ 采取"**从 26.2 源码提取常量 + 对拍测试**"策略(§5),防止凭记忆写错常量。

## 3. 掉落物物理模型(待实现期逐条与 26.2 mojmap 源码核对)

原版 ItemEntity 的 tick 主流程(以 1.21 系为参照,**26.2 数字以反编译源码为准**):

1. 物品为空 → 移除;拾取延迟倒计时;
2. **重力**: 无 no-gravity 时速度 Y 每 tick 减去重力常量(≈0.04);
3. **流体处理**: 浸泡在水/熔岩时,浮力调整 + 每轴阻力(≈0.8) + 气泡柱加速/下压;水中还会被水流(邻居 FluidState 的流向/流速)推动;
4. **空气中运动**: 每轴阻力(≈0.98),再按速度做移动;
5. **移动/碰撞**: 以实体 AABB 做方块碰撞(调用引擎统一碰撞逻辑,与"接住后反弹、落在方块上减速至停"等行为一致),碰撞后速度按原版规则衰减(触地时水平速度骤减、垂直反弹极小);
6. **触地摩擦**: 水平速度每 tick 大幅衰减直到静止;静止判定: 速度 < 阈值且在地面/水中;
7. 其它: 蜘蛛网、传送、下界传送门、气泡柱气泡粒子等(仿真只关心运动学部分)。

**实现策略**(关键决策): 不手写"抛物线公式",而是**把 ItemEntity 的 tick 语义翻译为独立仿真器 SimEngine**:

- 输入: 世界只读接口(方块状态/流体状态查询)、初始位置/速度/重力标志;
- 核心: 复刻上述分支,方块碰撞调用引擎公开碰撞 API(`Entity#move` 思路)或等价的碰撞形状查询;
- 输出: 逐 tick 位置点列 + 终止原因(静止/落地/出界/到达时长上限/被拾取判定);
- 常量集中在一个类 (`PhysicsConstants`,带注释标注来源 tick 行号),未来版本升级只需改常量表 + 对拍。

> 为什么不用"克隆实体塞进世界来模拟": 会造成可见重复实体、物品合并、渲染闪烁等副作用;也避免了对 protected tick 的依赖。→ 纯逻辑仿真器,附带少量 access widener/mixin 兜底(编码期确认)。

## 4. 总体架构: 单 jar,双端可用

```
trajectorylens/
├─ build.gradle / settings.gradle / gradle.properties / gradle wrapper (9.5.1)
├─ src/
│  ├─ main/java/…                    ← common(双端)
│  │  ├─ physics/SimEngine.java        纯逻辑仿真器(只依赖世界查询接口,不依赖渲染)
│  │  ├─ physics/PhysicsConstants.java 常量表(从 26.2 源码提取)
│  │  ├─ network/TrajectoryPackets.java v2 预留(空)
│  │  └─ TrajectoryLensMod.java        ModInitializer:注册命令(服务端调试命令)等
│  ├─ client/java/…                  ← 仅客户端
│  │  ├─ tracker/ItemTracker.java     客户端 tick: 圈定候选掉落物、调 SimEngine、缓存折线
│  │  ├─ render/TrajectoryRenderer.java  WorldRenderEvents 绘制折线/落点/ETA
│  │  ├─ config/ModConfig.java        键位、半径、数量上限、颜色、开关
│  │  └─ TrajectoryLensClient.java    ClientModInitializer
│  ├─ test/java/…                    无头单测(虚拟方块网格上的仿真)
│  └─ resources/
│     ├─ fabric.mod.json              environment: "*"(双端可装), 客户端逻辑按 client entrypoint 隔离
│     ├─ assets/…/icon.png
│     └─ *.accesswidener / mixins(按需)
└─ (dev)/ 对拍测试专用地图/脚本(gametest 或 /summon 脚本)
```

双端行为矩阵:

| 安装位置 | 行为 |
|---|---|
| 客户端(单机/联机) | 完整功能: 预测+渲染+按键/配置 |
| 纯服务端 | 仅加载 common;默认无可见功能(不崩溃); 附带调试命令 `/itemtrace simulate <x y z vx vy vz> [tick]` 在控制台/命令输出落点,供漏斗/红石/挂机点设计使用 |
| 服务端未装 Mod 的联机服务器 | 客户端 Mod 纯本地预测,照常可用(无需服务端!) |

Fabric API 依赖模块(26.2 对应版本已含): `fabric-lifecycle-events-v1`(ClientTickEvents/WorldRenderEvents)、`fabric-key-binding-api-v1`;可选 `fabric-command-api-v2`。能不写 mixin 就不写。

## 5. 精度保证: 对拍测试(核心工程手段)

仿真器"看起来对"不够,要证明它与原版一致:

1. **常量提取**: 编码期打开 Loom 生成的 26.2 mojmap 源码 `ItemEntity.tick()`,把每个字面量抄入 `PhysicsConstants` 并注释来源;
2. **单元测试(无头)**: 构造确定性虚拟世界(平面/台阶/水池/气泡柱),仿真输出与**手工推导的解析解**(纯重力抛物、地面滑动衰减)对比,误差 < 1e-6;
3. **世界内对拍**: 开发模式用命令一次投掷 20 个物品,真实实体每 tick 位置 vs 仿真轨迹逐点对比,渲染 overlay 显示最大偏差;纯重力场景目标平均误差 < 0.1 格;
4. 该测试同时作为后续 26.3/26.4 升级时的回归网。

## 6. 渲染设计(Blaze3D 内置管线,兼容 GL/Vulkan)

- 钩子: Fabric `WorldRenderEvents.AFTER_TRANSLUCENT`(具体回调名以 26.2 fabric-api 为准,备选 `LAST`);
- 画法: `RenderLayer.getLines()` + Tessellator 提交 `position_color` 顶点(相机相对坐标),**不碰裸 GL**,因此在默认 OpenGL 与实验 Vulkan 后端下均可用;
- 元素:
  1. 轨迹折线: 按 tick 采样点连成折线(≤ 128 段),颜色按速度或"未来时间"渐变;
  2. 落点标记: 静止点处画水平圆环 + 短竖线(类似原版选中框风格),若预测会滚远则画"第二落点→滚动段"分色;
  3. ETA: 落点上方小字(经 `HudRenderCallback`/屏幕文本,可开关);
  4. 可选: 半透明"将到点光圈"在地面投影。
- 相机裁剪: 距离 > 配置半径(默认 32 格)不画。

## 7. 可选二期方案(视你的需求)

**方案 B: 服务端权威轨迹广播(让别人也看到"别人扔的物品")**
- 服务端每 tick 对附近的 ItemEntity 跑同一个 SimEngine,把折线压缩(终点+每 4 tick 采样点)后经自定义 payload(`fabric-networking-api-v1`,仅当有本 Mod 客户端在线)发给周围玩家;
- 优点: 反作弊/严格权威、覆盖"别的玩家/生物掉落的物品",客户端零仿真成本;
- 代价: 带宽与实现复杂度上升、需处理实体生命周期事件;
- 本设计把 SimEngine 放在 common,天然可复用到 B 方案——**A(本地仿真)先落地,B 只是"换数据源"**,数据结构与渲染层不动。

## 附: 实体行走范围预测(已与用户确认的需求定稿, 待开工)

目标: 对"全部可行走实体"(按实体类型挑选)显示 **极限可达域** —— T 秒(默认 10s,可配置/指令参数)内
从当前位置按自身移动速度理论上限能到达的所有格子范围。注意它不是 AI 轨迹预测(AI 随机决策无法预知),
而是纯几何可达上界: AI 发呆/折返只会走得更小, 追击型目标(追玩家的僵尸)会接近该上界。

### 语义与边界(v1)
- 只算**陆地行走**: 移动速度取实体 MOVEMENT_SPEED 属性(跑步/疾跑不算, 取行走值)。
- 障碍规则: 完整方块/栅栏/关闭的门不可穿越; 可跳上 1 格(实体步高内); 可向下自由掉落;
  水面按实体是否会游泳处理(会游泳: 慢速格; 不会: 不可进入深水, 浅水正常); 头顶留空≥实体身高;
- 不做: 船/矿车/骑乘、开门、楼梯精确爬升(按可跳上处理)、末影人等瞬移/飞行实体(仅标记可行走者,
  飞行怪不可达域无意义——通过 isPathFindingEntity/isWalkable 能力过滤)。
- 性能: 一次可达域 BFS 半径 ≤ ~24 格(以 10s×速度折算步数上限), 单实体毫秒级, 异步线程计算+缓存;
  每实体每 ~0.5s 或移动超过 0.5 格重算一次; 同屏上限 ~8 个范围盘。

### 交互(独立开关, 与掉落物线分开)
- 独立按键(默认 R): 单独开/关范围盘显示(掉落物线仍归 G)。
- 指令(沿用服务器注册+网络包→客户端模式, 带 Tab 补全):
  - /trajectorylens range add <实体类型id>   (如 minecraft:zombie / villager; 重复累加)
  - /trajectorylens range clear             (清空=关闭范围显示)
  - /trajectorylens range list              (列出当前跟踪的实体类型及状态)
  - /trajectorylens range time <秒>         (设置预测时长, 默认 10)
- 配色: 复用现有"类型→颜色"体系(实体类型单独一套自动色板 + 指令可指定, 查询同上 /colors 分节)。

### 渲染(复用现有 Gizmo 方案, 无粒子无方块)
- 范围盘: 每可达格画半透明地面填充层(透明感玻璃盘), 边界(与不可达相邻的格子)描边高亮;
  类型色可区分多个实体; always-on-top 可配置;
- 与掉落物轨迹同屏不冲突(地面盘 vs 空中线)。

### 风险
- 可达上界对"会发呆的动物"显得偏大(语义上明确为上限, 配合 5s 短时档使用体验更好);
- 客户端寻路评价与原版 PathNavigation 存在小差异(不做完整 A*), 边缘地形(半砖/活板门)可能偏保守,
  后续可用真实实体走位对拍校正;
- 性能: 24 格半径 BFS 在最坏复杂地形下需控制节流(异步+缓存+上限)。
